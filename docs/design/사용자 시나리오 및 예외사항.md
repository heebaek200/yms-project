# 사용자 시나리오 및 예외사항

> YMS의 주요 사용자가 서비스를 어떤 순서로 이용하는지와 각 단계에서 발생할 수 있는 예외 상황을 정리합니다.  
> 본 문서는 요구사항 문서를 실제 사용자 흐름으로 연결하기 위한 시나리오 문서입니다.

## 1. 사용자 유형과 기본 전제

YMS에서는 사용자의 **전문 역할**, **워크스페이스 권한**, **프로젝트 권한**을 서로 구분합니다.

### 전문 역할

- CREATOR: 채널 운영자 또는 기획자
- EDITOR: 영상 편집자
- THUMBNAILER: 썸네일 작업자

한 사용자는 여러 전문 역할을 동시에 가질 수 있습니다.

### 워크스페이스 권한

- OWNER: 워크스페이스 전체 관리
- ADMIN: 멤버, 채널, 캠페인, 프로젝트와 재무 정보 관리
- MEMBER: 자신에게 허용된 프로젝트와 업무 기능 이용

### 프로젝트 권한

- EDIT: 프로젝트 조회 및 수정, 작업 관리 가능
- VIEW: 프로젝트 조회 및 채팅 가능, 프로젝트와 작업 수정 불가

CREATOR 역할을 가지고 있다는 이유만으로 워크스페이스 전체의 재무 정보가 자동으로 공개되지는 않습니다.

워크스페이스의 전체 비용, 수익, 손익과 ROI는 기본적으로 OWNER 또는 ADMIN만 조회할 수 있습니다.

## 2. 시나리오 1. 회원가입과 프로필 설정

### 주요 사용자

모든 사용자

### 정상 흐름

1. 사용자가 이메일, 비밀번호와 이름을 입력하여 회원가입합니다.
2. 사용자가 로그인합니다.
3. 최초 로그인 후 자신이 수행할 수 있는 전문 역할을 하나 이상 선택합니다.
4. CREATOR 역할을 선택한 경우 롱폼 및 쇼츠의 기본 조회수 1회당 예상 수익 단가를 입력할 수 있습니다.
5. 사용자가 프로필 설정을 저장합니다.
6. 시스템은 설정된 역할에 따라 이후 작업자 검색과 기본 화면 구성에 활용합니다.

조회수 1회당 수익 단가는 프로젝트의 YouTube 플랫폼 예상 수익을 계산할 때 사용하는 기본값입니다.

프로필의 기본 단가는 새로운 프로젝트에 적용할 초기값이며, 프로젝트에는 실제 적용된 조회수 1회당 수익 단가를 별도로 저장합니다.

### 예외 상황

#### EX-1.1. 전문 역할을 선택하지 않은 경우

사용자가 전문 역할을 하나도 선택하지 않은 상태에서는 프로필 설정을 완료할 수 없습니다.

화면에는 역할을 하나 이상 선택하도록 안내합니다.

#### EX-1.2. 올바르지 않은 조회수 1회당 수익 단가 입력

CREATOR가 조회수 1회당 수익 단가에 음수, 숫자가 아닌 문자열 또는 허용 범위를 벗어난 값을 입력한 경우 저장하지 않습니다.

화면에는 올바른 값을 입력하도록 안내합니다.

#### EX-1.3. 기본 조회수 1회당 수익 단가 변경

사용자가 프로필의 기본 단가를 변경하더라도 기존 프로젝트의 적용 단가가 자동으로 변경되어서는 안 됩니다.

기존 미확정 프로젝트에 새 기본값을 적용하려는 경우 사용자가 명시적으로 변경 범위를 선택해야 합니다.

## 3. 시나리오 2. 워크스페이스 생성과 멤버 초대

### 주요 사용자

OWNER, ADMIN, 초대받은 MEMBER

### 정상 흐름 A. 워크스페이스 생성

1. 사용자가 새 워크스페이스를 생성합니다.
2. 워크스페이스 이름과 기본 정보를 입력합니다.
3. 워크스페이스를 생성한 사용자는 자동으로 OWNER 권한을 가집니다.
4. OWNER는 멤버 관리 화면에서 함께 작업할 사용자를 이메일로 초대합니다.
5. 시스템은 초대를 대기 상태로 저장합니다.
6. 초대받은 사용자가 로그인 후 초대를 확인합니다.
7. 사용자가 초대를 수락하면 워크스페이스 MEMBER로 등록됩니다.

### 정상 흐름 B. 가입하지 않은 사용자 초대

1. OWNER 또는 ADMIN이 아직 가입하지 않은 이메일을 초대합니다.
2. 시스템은 해당 이메일에 대한 초대 정보를 대기 상태로 저장합니다.
3. 사용자가 해당 이메일로 회원가입합니다.
4. 로그인 후 대기 중인 워크스페이스 초대를 확인합니다.
5. 사용자가 초대를 수락하면 해당 워크스페이스에 참여합니다.

### 예외 상황

#### EX-2.1. 초대 거절

초대받은 사용자는 초대를 거절할 수 있습니다.

거절된 초대는 워크스페이스 멤버로 전환되지 않습니다.

#### EX-2.2. 초대 취소 후 수락 시도

OWNER 또는 ADMIN이 대기 중인 초대를 취소한 뒤 사용자가 해당 초대를 수락하려는 경우 참여할 수 없습니다.

시스템은 더 이상 유효하지 않은 초대임을 안내합니다.

#### EX-2.3. 이미 참여 중인 사용자 재초대

이미 워크스페이스의 멤버인 사용자를 다시 초대할 수 없습니다.

중복 멤버가 생성되지 않도록 서버에서도 참여 상태를 검증합니다.

#### EX-2.4. 마지막 OWNER의 권한 제거

워크스페이스에는 최소 한 명의 OWNER가 존재해야 합니다.

마지막 OWNER가 권한을 변경하거나 워크스페이스를 떠나려고 하는 경우 다른 멤버에게 소유권을 이전하도록 안내합니다.

## 4. 시나리오 3. 채널 등록과 캠페인 설정

### 주요 사용자

OWNER, ADMIN

### 정상 흐름 A. 채널 등록

1. OWNER 또는 ADMIN이 워크스페이스의 채널 관리 화면으로 이동합니다.
2. 채널명과 YouTube 채널 ID 또는 URL을 입력합니다.
3. 필요한 경우 채널 설명을 입력합니다.
4. 시스템은 채널을 워크스페이스에 등록합니다.
5. 이후 프로젝트 생성 시 등록된 채널을 선택할 수 있습니다.

초기 릴리스에서는 Google 계정 연동 없이 수동 등록이 가능해야 합니다.

### 정상 흐름 B. 캠페인 생성

1. OWNER 또는 ADMIN이 새 캠페인을 생성합니다.
2. 캠페인명, 설명, 시작일, 종료일과 상태를 입력합니다.
3. 캠페인을 저장합니다.
4. 이후 프로젝트를 생성할 때 해당 캠페인을 선택적으로 연결할 수 있습니다.

캠페인은 워크스페이스에 속하며 특정 채널을 직접 소유하지 않습니다.

### 예외 상황

#### EX-3.1. 다른 워크스페이스의 채널 접근

사용자가 현재 워크스페이스에 속하지 않은 채널 ID를 직접 요청에 포함하여 프로젝트에 연결하려는 경우 서버에서 차단합니다.

#### EX-3.2. 캠페인 없이 프로젝트 생성

캠페인은 선택 사항입니다.

일반 브이로그, 자체 기획 영상 등 별도의 캠페인이 필요하지 않은 프로젝트는 캠페인 없이 정상적으로 생성할 수 있어야 합니다.

#### EX-3.3. 하나의 프로젝트를 두 캠페인에 연결

하나의 프로젝트는 최대 하나의 캠페인에만 속할 수 있습니다.

기존 캠페인에 연결된 프로젝트를 다른 캠페인에 추가하려는 경우 기존 연결을 변경할 것인지 확인해야 합니다.

#### EX-3.4. 서로 다른 채널의 프로젝트를 하나의 캠페인에 포함

캠페인은 특정 채널에 귀속되지 않으므로 하나의 캠페인에 서로 다른 채널의 프로젝트를 포함할 수 있습니다.

이는 예외가 아니라 정상적인 사용 사례로 처리합니다.

## 5. 시나리오 4. 프로젝트 생성과 작업 배정

### 주요 사용자

OWNER, ADMIN, 프로젝트 소유자, EDIT 권한 사용자

### 정상 흐름

1. 사용자가 새 영상 프로젝트를 생성합니다.
2. 프로젝트 제목과 기획 내용을 입력합니다.
3. 워크스페이스에 등록된 채널을 선택합니다.
4. 필요한 경우 캠페인을 선택합니다.
5. 제작 마감일과 업로드 예정일을 입력합니다.
6. 프로젝트를 생성한 사용자는 프로젝트 소유자가 됩니다.
7. 프로젝트 참여자로 워크스페이스 멤버를 추가합니다.
8. 참여자에게 EDIT 또는 VIEW 권한을 부여합니다.
9. 프로젝트에 가편집, 종합 편집, 자막, 썸네일 등의 세부 작업을 생성합니다.
10. 각 작업에 담당자, 작업 기간과 작업자 지급 금액을 입력합니다.
11. 저장된 작업은 담당자의 일정과 대시보드에 반영됩니다.
12. 담당자에게 새 작업이 배정되었다는 알림을 제공합니다.

### 예외 상황

#### EX-4.1. 프로젝트에 참여하지 않은 사용자에게 작업 배정

해당 프로젝트의 참여자가 아닌 사용자는 작업 담당자로 지정할 수 없습니다.

담당자 선택 목록에서는 프로젝트 참여자만 표시하고 서버에서도 참여 여부를 검증합니다.

#### EX-4.2. 작업과 전문 역할 불일치

편집 관련 작업에 EDITOR 역할이 없는 사용자를 배정하려는 경우 경고 메시지를 표시합니다.

예:

> 해당 사용자는 영상 편집자 역할이 등록되어 있지 않습니다. 그래도 배정하시겠습니까?

전문 역할은 검색과 실수 방지를 위한 정보이며 실제 배정을 강제로 차단하지는 않습니다.

#### EX-4.3. 다른 워크스페이스의 캠페인 연결

현재 프로젝트와 다른 워크스페이스에 속한 캠페인은 연결할 수 없습니다.

#### EX-4.4. VIEW 권한 사용자의 수정 시도

VIEW 권한을 가진 사용자는 프로젝트와 작업 정보를 조회하고 채팅에 참여할 수 있지만 프로젝트 정보, 작업 배정과 작업 상태를 직접 수정할 수 없습니다.

화면에서는 수정 기능을 숨기거나 비활성화하고 서버에서도 권한을 재검증합니다.

## 6. 시나리오 5. 작업 수행과 프로젝트 협업

### 주요 사용자

EDITOR, THUMBNAILER, 기타 작업자, CREATOR

### 정상 흐름

1. 작업자가 로그인합니다.
2. 대시보드에서 자신에게 배정된 마감 예정 작업과 알림을 확인합니다.
3. 작업 일정을 선택하여 프로젝트 상세 화면으로 이동합니다.
4. 프로젝트 채팅에서 크리에이터 및 다른 참여자와 메시지를 주고받습니다.
5. 작업을 시작하면 상태를 진행 중으로 변경합니다.
6. 작업 중 요청이나 피드백을 채팅으로 확인합니다.
7. 작업이 끝나면 상태를 검수 요청으로 변경합니다.
8. 프로젝트 소유자 또는 권한이 있는 사용자가 결과물을 확인합니다.
9. 검수가 완료되면 작업 상태를 완료로 변경합니다.
10. 작업자는 자신의 정산 예정 금액과 향후 정산 상태를 확인할 수 있습니다.

편집자와 썸네일 작업자의 기본 사용 흐름에서는 워크스페이스 전체의 매출, 이익과 ROI가 필요하지 않습니다.

### 예외 상황

#### EX-5.1. 참여하지 않은 프로젝트 직접 접근

사용자가 주소창에 자신이 참여하지 않은 프로젝트 ID를 직접 입력할 수 있습니다.

서버는 프로젝트 참여 여부를 확인하고 권한이 없는 경우 403 Forbidden으로 처리합니다.

화면에서는 접근 권한이 없음을 안내하고 사용자가 접근 가능한 화면으로 이동시킵니다.

#### EX-5.2. 읽지 않은 채팅 메시지

사용자가 프로젝트 채팅을 확인하지 않은 동안 새 메시지가 도착한 경우 읽지 않은 메시지 수를 표시합니다.

채팅방을 확인하면 사용자별 마지막 확인 위치를 갱신합니다.

#### EX-5.3. 완료된 작업의 일반 수정

완료 상태의 작업을 다시 수정하거나 상태를 되돌려야 하는 경우 일반 작업자에게 무제한 수정 권한을 제공하지 않습니다.

프로젝트 소유자 또는 적절한 EDIT 권한 사용자가 업무 상황을 확인한 뒤 변경하도록 합니다.

#### EX-5.4. 재무 정보 접근

MEMBER인 편집자 또는 썸네일 작업자가 워크스페이스의 전체 수익, 비용, 손익 또는 ROI 화면에 직접 접근하려는 경우 권한을 확인하여 차단합니다.

자신의 작업자 지급 금액과 개인 정산 정보는 조회할 수 있습니다.

## 7. 시나리오 6. 비용과 실제 수익 관리

### 주요 사용자

OWNER, ADMIN

### 정상 흐름 A. 비용 등록

1. OWNER 또는 ADMIN이 비용 관리 화면으로 이동합니다.
2. 콘텐츠 제작 과정에서 발생한 비용을 등록합니다.
3. 비용 유형을 선택합니다.
4. 금액과 발생일을 입력합니다.
5. 비용의 귀속 대상을 하나 선택합니다.
   - 프로젝트
   - 캠페인
   - 채널
   - 워크스페이스
6. 시스템은 해당 Expense를 선택한 대상에 직접 귀속하여 저장합니다.

예를 들어 특정 프로젝트의 스튜디오 대관료는 프로젝트 비용으로, 여러 프로젝트를 위한 캠페인 공통 촬영비는 캠페인 비용으로 등록할 수 있습니다.

### 정상 흐름 B. 실제 수익 등록

1. OWNER 또는 ADMIN이 수익 관리 화면으로 이동합니다.
2. 수익 유형을 선택합니다.
3. 실제 발생한 금액과 발생일 또는 정산 기준일을 입력합니다.
4. 수익의 귀속 대상을 하나 선택합니다.
   - 프로젝트
   - 캠페인
   - 채널
   - 워크스페이스
5. 시스템은 Revenue를 선택한 대상에 직접 귀속하여 저장합니다.

예를 들어 특정 영상의 제휴 링크 수익은 프로젝트에, 여러 영상을 포함하는 브랜드 계약금은 캠페인에 귀속할 수 있습니다.

### 예외 상황

#### EX-6.1. 하나의 비용을 여러 대상에 동시 귀속

하나의 Expense를 프로젝트와 캠페인 등에 동시에 직접 귀속할 수 없습니다.

저장 시 정확히 하나의 귀속 대상만 선택해야 합니다.

#### EX-6.2. 하나의 수익을 여러 대상에 동시 귀속

하나의 Revenue를 프로젝트와 캠페인 등에 동시에 직접 귀속할 수 없습니다.

캠페인 수익을 프로젝트별로 임의 분배하려면 별도의 명시적인 기능이 필요하며 초기 릴리스에서는 지원하지 않습니다.

#### EX-6.3. 작업자 지급액의 중복 비용 등록

작업에 설정된 작업자 지급 금액은 프로젝트 제작비에 자동 포함됩니다.

동일한 금액을 별도의 Expense로 다시 입력하여 이중 집계해서는 안 됩니다.

#### EX-6.4. 상위 단위 수익의 임의 배분

채널에 귀속된 멤버십 수익이나 워크스페이스 전체 수익을 특정 프로젝트 또는 캠페인의 수익으로 자동 배분하지 않습니다.

원래 귀속된 단위에 그대로 보존합니다.

## 8. 시나리오 7. 작업자 정산

### 주요 사용자

OWNER, ADMIN, EDITOR, THUMBNAILER

### 정상 흐름 A. 관리자 정산

1. OWNER 또는 ADMIN이 정산 화면에서 대상 기간을 선택합니다.
2. 시스템이 해당 기간의 작업자별 지급 대상 작업을 집계합니다.
3. 정산이 DRAFT 상태로 생성됩니다.
4. 관리자가 작업 목록과 지급 예정 금액을 확인합니다.
5. 이상이 없으면 정산을 CONFIRMED 상태로 변경합니다.
6. 시스템은 확정 시점의 작업과 지급 금액을 스냅샷으로 보존합니다.
7. 실제 지급이 끝나면 관리자가 PAID 상태로 변경합니다.

### 정상 흐름 B. 작업자 정산 확인

1. 작업자가 로그인합니다.
2. 자신의 정산 화면으로 이동합니다.
3. 정산 대상 작업과 확정 금액을 확인합니다.
4. 현재 상태가 DRAFT, CONFIRMED 또는 PAID인지 확인합니다.

작업자는 워크스페이스 전체 정산 금액이나 다른 작업자의 지급액을 조회하지 않습니다.

### 예외 상황

#### EX-7.1. 취소된 프로젝트의 완료 작업

프로젝트가 취소되었더라도 이미 완료되어 지급 대상이 된 작업은 정산에 포함할 수 있습니다.

프로젝트 취소 자체를 이유로 작업자의 완료된 지급 항목을 자동 삭제하지 않습니다.

#### EX-7.2. 정산 확정 후 작업 단가 변경

정산이 CONFIRMED 상태가 된 이후 해당 작업의 지급 금액이 변경되더라도 확정된 정산 금액은 자동으로 바뀌지 않습니다.

확정 당시 스냅샷을 기준으로 유지합니다.

#### EX-7.3. PAID 정산 수정

PAID 상태의 정산은 일반적인 수정 기능으로 변경할 수 없습니다.

오류 정정이 필요한 경우 별도의 정정 절차를 설계합니다.

#### EX-7.4. 동일 작업의 중복 정산

이미 다른 정산에 포함된 작업이 다시 신규 정산에 포함되지 않도록 서버에서 중복 여부를 검증합니다.

## 9. 시나리오 8. 영상 업로드와 콘텐츠 가치 분석

### 주요 사용자

OWNER, ADMIN, 프로젝트 소유자

### 정상 흐름 A. 영상 업로드와 데이터 연결

1. 프로젝트의 필요한 작업이 완료됩니다.
2. 권한이 있는 사용자가 업로드한 YouTube 영상의 URL 또는 영상 ID를 입력합니다.
3. 프로젝트 상태를 UPLOADED로 변경합니다.
4. 실제 업로드 일시를 저장합니다.
5. 시스템이 YouTube API를 통해 조회수 등 콘텐츠 성과 데이터를 가져옵니다.
6. 프로젝트에 설정된 조회수 1회당 수익 단가를 이용하여 YouTube 플랫폼 예상 수익을 계산할 수 있습니다.
7. 조회수, 좋아요 등의 콘텐츠 성과와 조회수 1회당 수익 단가 기반 예상 수익을 참고 정보로 표시합니다.

조회수 1회당 수익 단가 기반 예상 수익은 실제 수익으로 확정된 값이 아니며 실제 ROI 계산에는 포함하지 않습니다.

### 정상 흐름 B. 프로젝트 재무 성과

1. 시스템이 프로젝트 작업에 연결된 작업자 지급 금액을 집계합니다.
2. 프로젝트에 직접 귀속된 Expense를 합산합니다.
3. 프로젝트에 직접 귀속된 실제 Revenue를 합산합니다.
4. 실제 비용과 실제 수익을 기준으로 손익을 계산합니다.
5. 실제 비용이 존재하는 경우 ROI와 수익/비용 배수를 계산합니다.
6. 조회수 등 콘텐츠 성과는 재무 지표와 별도로 함께 표시합니다.

기본 계산은 다음과 같습니다.

```text
손익 = 실제 수익 - 실제 비용

ROI = (실제 수익 - 실제 비용) ÷ 실제 비용 × 100

수익/비용 배수 = 실제 수익 ÷ 실제 비용
```

### 정상 흐름 C. 캠페인 재무 성과

1. OWNER 또는 ADMIN이 캠페인 상세 화면을 조회합니다.
2. 시스템이 캠페인에 직접 귀속된 Expense를 집계합니다.
3. 캠페인에 포함된 프로젝트의 작업자 지급 금액과 프로젝트 Expense를 집계합니다.
4. 캠페인에 직접 귀속된 실제 Revenue를 집계합니다.
5. 캠페인에 포함된 프로젝트의 실제 Revenue를 집계합니다.
6. 실제 비용과 실제 수익을 이용하여 캠페인 손익과 ROI를 계산합니다.
7. 각 프로젝트의 조회수 등 콘텐츠 성과를 함께 표시합니다.

채널 또는 워크스페이스에 귀속된 비용과 수익은 캠페인에 자동 배분하지 않습니다.

### 예외 상황

#### EX-8.1. 존재하지 않는 YouTube 영상

사용자가 잘못된 URL 또는 영상 ID를 입력하고 외부 API에서도 영상을 확인할 수 없는 경우 프로젝트에 연결하지 않습니다.

화면에는 URL 또는 영상 ID를 다시 확인하도록 안내합니다.

외부 API 장애와 사용자의 잘못된 입력은 서로 다른 오류로 처리합니다.

#### EX-8.2. YouTube API 호출 실패

외부 API 장애 또는 할당량 제한으로 데이터를 갱신하지 못한 경우 기존에 저장된 마지막 성공 데이터를 유지합니다.

사용자에게 마지막 갱신 시각과 현재 갱신 실패 상태를 표시합니다.

#### EX-8.3. 실제 수익이 0원인 프로젝트

실제 수익이 0원인 프로젝트도 정상적인 분석 대상입니다.

제작비만 발생한 프로젝트는 손실 프로젝트로 표시할 수 있어야 합니다.

#### EX-8.4. 실제 비용이 0원인 경우

실제 비용이 0원인 프로젝트나 캠페인에서는 ROI 계산의 분모가 0이 되므로 ROI를 계산하지 않습니다.

화면에는 ROI를 0%로 오해할 수 있는 값 대신 계산 불가 또는 해당 없음 상태로 표시합니다.

#### EX-8.5. 조회수 기반 예상 수익만 존재하는 경우

실제 Revenue가 없고 조회수 1회당 수익 단가 기반 예상 수익만 존재하는 프로젝트에서는 예상 수익을 참고 정보로 표시합니다.

예상 수익을 실제 매출로 간주하여 ROI를 계산하지 않습니다.

#### EX-8.6. 캠페인 수익과 프로젝트 수익의 중복 집계

캠페인에 직접 등록한 협찬 수익과 프로젝트에 직접 등록한 수익은 서로 별개의 Revenue입니다.

하나의 수익 항목을 양쪽에 동시에 귀속하여 중복 집계할 수 없습니다.

## 10. 시나리오 간 주요 연결 관계

YMS의 사용자 흐름은 각 기능이 독립적으로 끝나는 구조가 아닙니다.

```text
회원가입 및 프로필 설정
        ↓
워크스페이스 생성 또는 초대 수락
        ↓
채널 등록
        ↓
캠페인 생성(선택)
        ↓
프로젝트 생성
        ↓
프로젝트 참여자와 작업 배정
        ↓
작업 수행 · 채팅 · 검수
        ↓
작업 완료 및 작업자 정산
        ↓
영상 업로드 및 YouTube 데이터 연결
        ↓
Expense / Revenue 기록
        ↓
프로젝트 및 캠페인 재무 성과 분석
```

프로젝트 참여 여부와 권한은 작업, 채팅과 수정 기능에 영향을 줍니다.

작업에 설정된 지급 금액은 작업자의 정산과 프로젝트 제작비 양쪽에 영향을 줍니다.

Expense와 Revenue의 귀속 대상은 프로젝트 및 캠페인 재무 성과 집계 범위를 결정합니다.

프로젝트가 캠페인에 속하지 않아도 독립적인 협업과 성과 분석이 가능해야 합니다.

## 11. 공통 예외 처리 원칙

### 11.1. 서버 권한 검증

화면에서 버튼이나 메뉴를 숨기는 것만으로 권한을 제어해서는 안 됩니다.

워크스페이스, 프로젝트, 재무 정보에 대한 모든 주요 요청은 서버에서 사용자의 권한을 다시 확인합니다.

### 11.2. 입력값 검증

클라이언트에서 기본적인 사용자 편의 검증을 수행하더라도 서버에서도 동일하게 데이터 유효성을 검증합니다.

### 11.3. 외부 API 오류 구분

YouTube API 사용 시 다음 상황을 구분합니다.

- 사용자가 입력한 영상 정보가 올바르지 않은 경우
- 외부 서비스에서 영상을 조회할 수 없는 경우
- 인증 또는 권한이 부족한 경우
- 외부 API 자체가 실패한 경우
- 할당량 제한으로 조회할 수 없는 경우

### 11.4. 금액 0원 처리

비용 또는 수익이 0원인 것은 오류 데이터로 간주하지 않습니다.

다만 0으로 나누는 ROI 등의 지표는 별도로 처리하여 화면 오류나 잘못된 수치가 표시되지 않도록 합니다.

### 11.5. 재무 정보와 협업 정보 분리

일반 작업자에게 필요한 작업 일정, 채팅, 검수와 개인 정산 정보는 계속 제공해야 합니다.

반면 워크스페이스 전체 비용, 수익, 손익과 ROI는 재무 정보 접근 권한이 있는 사용자에게만 제공합니다.

이 원칙을 통해 YMS는 **크리에이터와 편집자 간의 협업 서비스**라는 기본 가치를 유지하면서, 운영자에게는 **콘텐츠 제작에 투입한 비용으로부터 얼마의 가치를 만들었는지 관리하는 기능**을 함께 제공합니다.
