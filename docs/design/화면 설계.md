# 화면 설계

> YMS의 전체 화면 목록과 각 화면의 목적, 접근 권한, 핵심 UI 컴포넌트를 정의합니다.  
> 본 문서는 요구사항 및 사용자 시나리오를 화면 단위로 구체화한 기준 문서입니다.

> **UI 표기 기준:** 사용자에게 노출되는 화면 문구는 `제작팀`으로 통일합니다. 컴포넌트명, API 필드와 같은 내부 기술 식별자는 `Workspace` / `workspace`를 유지합니다.

## 1. 화면 설계 원칙

YMS는 **크리에이터와 편집자·썸네일 작업자 사이의 제작 협업**을 기본 가치로 하며, OWNER와 ADMIN에게는 콘텐츠 제작 비용과 실제 수익을 연결하여 성과를 분석하는 운영 기능을 추가로 제공합니다.

따라서 모든 사용자가 동일한 메뉴와 재무 정보를 보는 구조로 설계하지 않습니다.

- 일반 작업자는 자신에게 필요한 프로젝트, 작업, 일정, 채팅, 알림과 개인 정산 정보를 우선 확인합니다.
- OWNER와 ADMIN은 제작팀 운영, 채널, 프로젝트 그룹, 비용, 수익, 전체 정산과 재무 분석 기능에 접근할 수 있습니다.
- 프로젝트의 EDIT / VIEW 권한은 프로젝트 협업 범위를 결정하며 제작팀 전체 재무 정보 접근 권한을 의미하지 않습니다.
- 제작팀은 로그인 이후 대부분의 화면에서 현재 작업 범위를 결정하는 기준 컨텍스트로 사용합니다.
- 데스크톱과 모바일에서 동일한 핵심 기능과 조작 체계를 제공하되, 모바일의 본문은 카드·목록 중심의 세로형 레이아웃을 우선합니다.

## 2. 공통 레이아웃 및 공통 UI

현재 제작팀을 작업 범위로 사용하는 인증 이후 주요 화면은 공통 `AppLayout`을 사용합니다. SCR-02 프로필 설정과 SCR-03 제작팀 선택·생성·초대는 제작팀 컨텍스트가 확정되기 전에도 접근해야 하므로 `AppLayout` 외부에 둡니다.

### 공통 헤더

- YMS 로고
- 현재 제작팀 표시 및 전환
- 주요 화면 이동 메뉴
- 읽지 않은 알림 배지
- 사용자 프로필 메뉴

제작팀 전환 메뉴에는 참여 중인 제작팀 목록과 함께 SCR-03 `/workspaces`로 이동하는 `전체 제작팀 보기` 진입점을 제공합니다. 현재 제작팀의 멤버, 채널과 업무 유형을 관리하는 기능은 SCR-03과 구분하여 `/workspace/settings`에서 제공합니다.

### 공통 내비게이션

메뉴는 화면 폭과 관계없이 다음 순서와 위치 체계를 유지합니다.

| 순서 | 메뉴 | 표시 대상 | Route | 비고 |
| --- | --- | --- | --- | --- |
| 1 | 대시보드 | 모든 제작팀 멤버 | `/dashboard` | SCR-05 |
| 2 | 프로젝트 | 모든 제작팀 멤버 | `/projects`, `/project-groups` | SCR-07 프로젝트와 SCR-06 프로젝트 그룹이 같은 상위 메뉴 공유 |
| 3 | 메신저 | 모든 제작팀 멤버 | `/messenger` | SCR-09, 실제 대화 접근은 프로젝트 참여 권한 확인 |
| 4 | 정산 관리 `🧾` | OWNER, ADMIN | `/workspace/settlements` | SCR-11A |
| 4 | 내 정산 `💰` | MEMBER | `/my/settlements` | SCR-11B, 같은 메뉴 위치를 사용하지만 별개 기능 |
| 5 | 분석 | OWNER, ADMIN | `/analytics` | SCR-12, 관리 영역 시작 |
| 6 | 비용·수익 | OWNER, ADMIN | `/finance` | SCR-10 |
| 7 | 제작팀 관리 | OWNER, ADMIN | `/workspace/settings` | SCR-04 |

일반 업무 영역과 관리 영역은 각각 둥근 테두리를 가진 메뉴 그룹으로 표시합니다. 프로젝트 그룹은 상단 메뉴를 별도로 차지하지 않고 프로젝트 메뉴 안의 두 번째 탭으로 제공합니다.

프로젝트와 프로젝트 그룹은 상위 메뉴와 탭 위치만 공유합니다. 각각 별도 Route, 목록, 상세, 생성·수정 폼, 권한 검사와 조회 로직을 사용합니다. `/project-groups`와 `/project-groups/{projectGroupId}`에서도 상단 프로젝트 메뉴를 활성 상태로 유지합니다.

역할에 허용되지 않은 메뉴는 표시하지 않되, 숨김 처리를 보안 수단으로 사용하지 않고 Route와 서버에서도 권한을 검증합니다. 현재 Route에 해당하는 메뉴에는 활성 상태와 `aria-current`를 제공합니다.

미구현 화면도 위 Route를 선점하고 `AppLayout` 안에서 다음 공통 준비 중 상태를 표시합니다.

> **{기능명}, 지금 열심히 편집 중이에요 🎬**<br>
> 메뉴와 가는 길은 먼저 열어 두었어요. 완성되는 대로 멋지게 선보일게요.

준비 중 화면에는 `대시보드로 이동` 버튼을 제공하며 별도 뒤로 가기 버튼은 제공하지 않습니다.

### 공통 알림 Drawer

별도의 전체 화면으로 분리하지 않고 모든 인증 화면에서 열 수 있는 Drawer 또는 Popover 형태로 제공합니다.

표시 대상:

- 새 작업 배정
- 작업 상태 변경 및 검수 요청
- 프로젝트 채팅 메시지
- 제작팀 초대
- 개인 정산 상태 변경

기능:

- 전체 / 읽지 않음 필터
- 최근 알림 목록
- 읽음 처리
- 관련 프로젝트 또는 화면 이동

### 공통 반응형 원칙

- 데스크톱: 좌우 분할, 테이블, 월간 캘린더 등 넓은 화면 활용
- 모바일: 카드, 주간 일정 또는 Agenda View, 단일 컬럼 중심
- 공통 헤더는 데스크톱과 모바일 모두 제작팀·알림·사용자 영역과 업무 메뉴 영역으로 구성된 동일한 2단 구조를 유지
- 모바일에서도 주요 메뉴를 별도 햄버거 메뉴나 Drawer 안에 숨기지 않고 동일한 메뉴 행과 순서를 유지
- 화면 폭보다 긴 메뉴 행은 가로로 탐색할 수 있게 하고, 현재 활성 메뉴가 보이지 않으면 보이는 위치로 자동 이동
- 메뉴 이름과 아이콘은 화면 크기에 따라 다른 의미나 위치 체계로 변경하지 않으며 모바일 터치 영역을 충분히 확보
- 수정 권한이 없는 사용자는 단순히 버튼을 숨기는 것에 그치지 않고 서버에서도 권한을 검증합니다.

### 공통 접근 불가 및 리소스 확인 상태

사용자가 URL, 알림 또는 저장된 링크로 특정 기능에 직접 접근했으나 현재 제작팀에서 이용할 수 없는 경우 자동으로 다른 화면으로 보내지 않고 다음 전용 상태를 표시합니다.

> **이 기능을 이용할 수 없어요**<br>
> 현재 선택된 제작팀은 ‘{제작팀명}’입니다.<br>
> 다른 제작팀에서 이용하려던 기능이라면 제작팀을 전환해 주세요.

`제작팀 전환`과 `대시보드로 이동` 동작을 함께 제공합니다. 화면을 사용하는 동안 역할이 변경되어 API가 403을 반환한 경우에도 같은 상태를 사용합니다.

다른 제작팀 소속 리소스를 열었거나 권한과 리소스 존재 여부를 구체적으로 구별해서는 안 되는 경우에는 다음 상태를 사용합니다.

> **현재 제작팀에서는 이 항목을 찾을 수 없어요**<br>
> 현재 선택된 제작팀은 ‘{제작팀명}’입니다.

이 상태에는 `제작팀 전환`과 `{기능명} 목록으로 이동` 동작을 제공합니다. 두 상태는 같은 공통 컴포넌트를 사용하고 제목, 설명과 보조 이동 경로만 상태에 맞게 변경합니다.

### 인증 후 보호 라우팅 원칙

존재하는 Route에 직접 접근하거나 새로고침한 경우 다음 순서로 상태를 검증합니다.

1. 인증 여부
2. `profileSetupRequired`에 따른 프로필 설정 완료 여부
3. Workspace 목록 조회 및 저장된 Workspace 접근 권한
4. 현재 탭의 Workspace 선택 여부

전문 역할을 나타내는 `roles` 배열은 프로필 설정 완료 여부의 대체 기준으로 사용하지 않습니다.

| 접근 조건 | 이동 결과 |
| --- | --- |
| 비인증 사용자가 보호 화면 접근 | SCR-01 `/` |
| 프로필 설정이 필요한 사용자가 SCR-03 또는 Workspace 하위 화면 접근 | SCR-02 `/profile-setup` |
| 프로필 설정 완료 후 현재 Workspace가 없는 사용자가 Workspace 하위 화면 접근 | SCR-03 `/workspaces` |
| 유효한 현재 Workspace가 있는 사용자가 `/` 접근 | SCR-05 `/dashboard` |
| 인증된 사용자가 `/profile-setup` 접근 | 프로필 조회·수정 화면 허용 |
| 프로필 설정을 완료한 사용자가 `/workspaces` 접근 | 제작팀 선택·생성·초대 화면 허용 |
| 역할상 허용되지 않은 Workspace 기능 Route에 직접 접근 | 현재 제작팀을 표시하는 공통 접근 불가 화면 |
| 현재 제작팀에 속하지 않은 상세 리소스 접근 | 존재 여부를 노출하지 않는 공통 리소스 확인 상태 |
| 존재하지 않는 URL 접근 | 인증 상태와 관계없이 404 화면 |

비인증 사용자가 보호 URL로 직접 접근했더라도 로그인 후 원래 URL로 복귀시키지 않습니다. 항상 프로필 설정, Workspace 선택, Dashboard 순서의 표준 진입 흐름을 적용하며 별도의 `returnUrl`은 저장하지 않습니다.

Workspace 목록과 저장된 선택값을 검증하는 동안에는 빈 화면이나 중간 리다이렉트를 노출하지 않습니다. 애니메이션과 `제작팀 정보를 확인하고 있습니다.` 문구가 포함된 전용 진행 상태를 즉시 표시하고, 응답이 도착하면 인위적인 최소 대기 시간 없이 다음 화면으로 전환합니다.

Workspace 목록 조회 실패는 참여 Workspace가 없는 상태로 간주하지 않습니다. 전용 오류 상태와 `다시 시도` 동작을 제공하고, 재시도 중에는 버튼을 비활성화한 뒤 `다시 확인하는 중...`처럼 진행 상태를 명확히 표시합니다.

### 브라우저 세션 및 Workspace 복원 정책

- 같은 브라우저에서는 하나의 로그인 계정만 사용하며 인증 상태를 모든 탭이 공유합니다.
- 인증 상태는 브라우저 공용 저장소에 보관하여 브라우저를 다시 열어도 로그아웃 또는 토큰 만료 전까지 복원합니다.
- 로그인, 로그아웃과 인증 만료는 모든 탭에 전파합니다.
- 로그아웃 시 모든 탭의 인증 상태와 탭별 현재 Workspace를 제거하되, 사용자별 마지막 Workspace ID는 유지합니다.
- 각 탭의 현재 Workspace는 탭 세션 저장소에 보관하여 독립적으로 유지합니다. 한 탭의 일반적인 Workspace 전환이 이미 열린 다른 탭의 현재 Workspace를 변경해서는 안 됩니다.
- Workspace를 선택하면 현재 탭의 선택값과 사용자별 마지막 선택값을 함께 갱신합니다.
- 사용자별 마지막 Workspace ID는 브라우저 공용 저장소에 보관하고, 새 탭 또는 다음 브라우저 방문에서 복원 후보로 사용합니다.
- 복원 후보는 Workspace 목록에서 현재 접근 권한이 확인된 경우에만 현재 Workspace로 사용합니다.
- 저장값이 없거나 권한이 사라졌으면 첫 번째 Workspace를 자동 선택하지 않고 SCR-03으로 이동합니다.
- 권한 상실이 확인되면 해당 Workspace를 사용하는 모든 탭에 무효 상태를 전파하고 SCR-03으로 이동합니다. 다른 Workspace를 사용 중인 탭에는 영향을 주지 않습니다.
- 무효화된 Workspace가 사용자별 마지막 선택값이면 해당 저장값도 제거합니다.

### Workspace 전환 시 Route 처리

- 목록 화면에서 제작팀을 전환하면 새 제작팀의 같은 기능 목록 Route를 유지합니다.
- 상세 화면에서 제작팀을 전환하면 이전 제작팀의 리소스 ID와 선택 상태를 제거하고 새 제작팀의 같은 기능 목록 Route로 이동합니다.
- 새 제작팀에도 적용 가능한 검색과 필터 상태는 가능한 범위에서 유지합니다.
- 전환 완료 시 `{제작팀명} 제작팀으로 전환했습니다.`라는 정보성 안내만 표시하고 권한 부족 또는 이전 리소스 부재를 전환 메시지로 설명하지 않습니다.
- 새 제작팀에서 현재 기능을 사용할 수 없으면 Route를 유지하고 공통 접근 불가 화면을 표시합니다.
- 역할에 따라 같은 메뉴 위치를 공유하는 서로 다른 기능으로 자동 이동하지 않습니다. 예를 들어 `/workspace/settlements`에서 MEMBER인 제작팀으로 전환해도 `/my/settlements`로 자동 전환하지 않습니다.

## 3. 전체 화면 목록

| 화면 ID | 화면명 | 주요 사용자 | 핵심 목적 |
| --- | --- | --- | --- |
| SCR-01 | 로그인 / 회원가입 | 비인증 사용자 | 계정 생성 및 로그인 |
| SCR-02 | 프로필 설정 | 인증 사용자 | 전문 역할 및 개인 기본 설정 |
| SCR-03 | 제작팀 선택 / 생성 / 초대 | 인증 사용자 | 사용할 제작팀 진입 |
| SCR-04 | 제작팀 관리 | OWNER, ADMIN | 멤버와 채널 관리 |
| SCR-05 | 메인 대시보드 및 스케줄러 | 제작팀 멤버 | 개인 업무와 전체 일정 확인 |
| SCR-06 | 프로젝트 그룹 관리 | OWNER, ADMIN | 여러 프로젝트를 프로젝트 그룹 단위로 관리 |
| SCR-07 | 프로젝트 목록 / 생성 / 보관함 | 제작팀 멤버 | 프로젝트 탐색 및 생성 |

# SCR-04. 제작팀 관리

> 와이어프레임: [GitHub Pages에서 보기](https://heebaek200.github.io/yms-project/design/wireframes/scr-04-workspace-admin.html)

## 목적

제작팀의 멤버와 YouTube 채널을 관리합니다.

제작팀 관리 기능과 프로젝트 협업 기능을 분리하여 일반 작업자에게 불필요한 관리 UI가 노출되지 않도록 합니다.

## 접근 권한

- OWNER
- ADMIN

일반 MEMBER는 접근할 수 없습니다.

## 핵심 컴포넌트

제작팀 관리의 하위 영역은 `/workspace/settings`를 공통 Route로 사용하고 Query Parameter로 선택 탭을 유지합니다.

- 멤버 관리: `/workspace/settings?tab=members`
- 채널 관리: `/workspace/settings?tab=channels`
- 작업 종류 관리: `/workspace/settings?tab=task-types`

탭 선택은 새로고침과 직접 URL 접근 후에도 유지합니다. Query Parameter가 없거나 알 수 없는 `tab` 값이면 `channels`로 보정합니다. 탭 메뉴는 별도 탭 위젯 로직을 두지 않고 `nav` 안의 URL `Link`로 구성하며, 현재 링크는 `aria-current="page"`로 표시합니다. 사용자는 일반 링크와 동일하게 `Tab`으로 이동하고 `Enter`로 선택할 수 있습니다. `members` 탭의 실제 기능은 #35에서 구현합니다.

### 멤버 관리 탭

- 상단: 멤버 검색·필터와 멤버 목록
- 하단: 발송한 초대 내역
- 새 멤버 초대

멤버 목록에는 이름, 이메일, 전문 역할, 제작팀 권한, 멤버 상태와 논리 삭제되지 않은 소유 프로젝트 수를 표시합니다. 제작팀 권한의 표시명은 `소유자(OWNER)`, `관리자(ADMIN)`, `멤버(MEMBER)`를 사용합니다. 멤버 상태는 `활동 중(ACTIVE)`, `탈퇴(LEFT)`, `제외됨(REMOVED)`으로 표시합니다.

최초 진입 시 ACTIVE 멤버만 표시합니다. 이름·이메일 검색, 멤버 상태, 전문 역할과 제작팀 권한 필터를 제공하며 여러 조건은 AND로 결합합니다. 복수 전문 역할을 가진 사용자는 선택한 전문 역할을 하나라도 포함하면 일치합니다. LEFT와 REMOVED 멤버는 이력만 표시하고 권한 변경·제외 액션을 제공하지 않습니다.

### 멤버 권한 변경과 제외

- OWNER만 다른 ACTIVE 멤버의 제작팀 권한을 변경할 수 있습니다.
- OWNER는 다른 사용자를 OWNER로 승격할 수 있으며 복수 OWNER를 허용합니다.
- 마지막 ACTIVE OWNER는 강등하거나 제외할 수 없습니다.
- OWNER는 다른 ACTIVE OWNER가 있을 때만 자신의 권한을 ADMIN 또는 MEMBER로 낮출 수 있습니다.
- ADMIN은 일반 MEMBER만 제외할 수 있고 OWNER·ADMIN 변경·제외와 사용자 승격은 할 수 없습니다.
- 자기 자신을 제외하는 `제작팀 나가기`는 이 화면에서 제공하지 않습니다.

권한 변경은 모달에서 현재 권한과 변경 가능한 권한을 함께 표시합니다. ADMIN과 MEMBER 사이의 변경은 이 모달에서 바로 저장합니다.

OWNER 승격 또는 강등은 첫 모달에서 저장을 선택해도 즉시 적용하지 않고 전용 2단계 확인 모달로 이동합니다. 확인 모달에는 대상 멤버와 `관리자 → 소유자`, `소유자 → 멤버`처럼 변경 전후 권한을 크게 표시하고 다음 규칙을 적용합니다.

- OWNER 승격은 왕관 아이콘과 보라색 계열 강조를 사용하고, 다른 멤버의 권한 변경과 OWNER 지정 등 모든 제작팀 관리 권한을 갖게 됨을 안내합니다.
- OWNER 강등은 경고 아이콘과 붉은색 계열 강조를 사용하고, 다른 멤버의 권한과 OWNER를 더 이상 관리할 수 없음을 안내합니다.
- 자기 자신을 강등할 때는 다른 OWNER만 OWNER 권한을 다시 부여할 수 있음을 별도 경고로 표시합니다.
- 대상 멤버의 이메일을 직접 입력해 일치한 경우에만 `소유자로 변경` 또는 `소유자 권한 해제` 최종 버튼을 활성화합니다.
- `돌아가기` 또는 확인 모달 닫기는 권한 선택값을 유지한 채 첫 권한 변경 모달로 돌아갑니다.
- 이메일 재입력은 오조작을 줄이는 화면 확인 절차이며, 마지막 ACTIVE OWNER와 요청자 권한은 서버가 최종 요청 시점에 다시 검증합니다.

현재 편집 대상이 마지막 ACTIVE OWNER이면 이메일 재입력 단계까지 진행시키지 않습니다. SCR-04는 기존 멤버 목록 조회에 `status=ACTIVE`, `workspaceRole=OWNER` 조건을 적용해 전체 ACTIVE OWNER 수를 확인하고 다음과 같이 처리합니다.

- 권한 선택 모달을 열 때 최신 OWNER 수를 조회합니다.
- 마지막 OWNER이면 ADMIN·MEMBER 선택지를 비활성화하고 `다른 멤버를 소유자로 지정한 뒤 권한을 변경해 주세요.` 안내를 표시합니다.
- 2단계 확인 모달로 이동하기 직전 같은 조건으로 다시 조회합니다.
- 조회하지 못한 경우에는 강등을 진행하지 않고 재시도를 안내합니다.
- 별도 API Path는 추가하지 않으며 최종 PATCH 요청의 서버 검증을 유지합니다.

현재 사용자가 자신을 MEMBER로 변경하면 현재 URL을 유지하고 공통 접근 불가 화면을 표시합니다. ADMIN으로 변경하면 관리 화면을 유지합니다.

멤버 제외는 별도 확인 모달을 사용하고 실제 행을 삭제하지 않고 REMOVED 상태로 변경합니다. 일반 ADMIN·MEMBER 제외는 기존 확인 모달을 사용합니다. 다른 ACTIVE OWNER를 제외할 때는 강등과 같은 수준의 전용 위험 확인을 적용하여 `소유자 → 제외됨`, 즉시 제작팀 접근과 모든 관리 권한을 잃는다는 점을 표시하고 대상 이메일이 일치할 때만 `소유자를 제작팀에서 제외` 버튼을 활성화합니다.

대상 멤버의 `ownedProjectCount`가 1 이상이면 일반 또는 위험 확인 모달에 진입시키지 않고 다음 안내와 소유 프로젝트 목록 이동 동작을 표시합니다. 보관 Project도 수에 포함하고 논리 삭제 Project는 제외합니다.

> 이 멤버가 소유한 프로젝트가 {N}개 있습니다. 프로젝트 소유권을 다른 활동 중인 멤버에게 이전한 뒤 제작팀에서 제외해 주세요.

서버에서 동일 충돌을 반환한 경우 멤버 목록을 갱신하고 같은 안내를 표시합니다. 제외 성공 시 대상의 다른 프로젝트 참여도 비활성화합니다. 재초대 후 수락해도 이전 소유권과 참여 상태는 자동 복구하지 않습니다.

### 멤버 초대 모달

- 이메일 입력
- 초대 발송

초대 시 제작팀 권한을 선택하지 않으며 수락한 사용자는 항상 MEMBER로 참여합니다. ACTIVE 멤버 또는 동일 이메일의 유효한 PENDING 초대가 있으면 모달 입력 필드에 오류를 표시합니다. LEFT·REMOVED 멤버는 다시 초대할 수 있고 수락하면 기존 멤버 상태를 ACTIVE·MEMBER로 복구하되 이전 프로젝트 소유권과 참여 상태는 자동 복구하지 않습니다.

### 초대 내역

초대 내역은 멤버 목록 아래의 별도 영역에 표시하며 최근 발송 순으로 정렬합니다. 초기 필터는 유효한 `대기 중(PENDING)`이고 `전체 / 대기 중 / 수락 / 거절 / 취소 / 만료됨` 필터를 제공합니다. `만료됨`은 PENDING 상태와 `expiresAt`을 조합한 화면 파생 상태이며 별도 API·DB Enum으로 저장하지 않습니다.

유효한 PENDING 초대에만 `초대 취소`를 표시합니다. 재전송 전용 기능은 제공하지 않으며 다시 초대하려면 이메일 초대 폼에서 새 초대를 생성합니다.

### 채널 관리 탭

- 등록 채널 목록
- 채널명
- YouTube Channel ID / URL
- 설명
- YouTube 연동 상태
- 활성 / 비활성 상태
- 롱폼·쇼츠 기본 예상 수익 단가
- 채널 추가
- 채널 수정
- 채널 삭제

채널 등록과 수정 시 채널명만 필수로 입력합니다. YouTube Channel ID, URL, 설명과 롱폼·쇼츠 기본 단가는 선택값이며, 이름만으로 수동 등록할 수 있습니다. ID나 URL이 입력되어 있어도 실제 연동 절차를 완료하기 전에는 `연동됨`으로 표시하지 않습니다.

채널 생성·수정 모달에는 접지 않은 `예상 수익 설정` 영역을 항상 표시합니다. 단가 입력 필드에는 숫자 플레이스홀더를 사용하지 않고 다음 안내를 별도 영역에 표시합니다.

- 처음 설정할 때 참고할 수 있는 예시입니다.
- 롱폼 약 3.00원/조회 · 쇼츠 약 0.20원/조회
- 채널과 콘텐츠에 따라 실제 수익은 달라질 수 있습니다.

사용자는 숫자 뒤에 `원` 또는 `원/조회`를 입력하거나 올바른 천 단위 쉼표를 사용할 수 있습니다. 포커스를 잃으면 단위와 쉼표를 제거한 숫자 문자열로 정규화하고 임의 문자가 섞인 값은 자동 변환하지 않습니다. 입력하지 않은 단가는 0원으로 저장하며 `단가는 0 이상의 숫자로 입력해 주세요. 소수점 여섯째 자리까지 허용됩니다.`를 검증 문구로 사용합니다. Channel 단가 변경은 기존 YouTube 게시물의 적용 단가를 자동으로 변경하지 않습니다.

연동 상태는 `수동 등록(MANUAL)`, `연동됨(CONNECTED)`, `연동 오류(ERROR)`를 목록에서 서로 구분합니다. 실제 연동을 해제한 이력을 나타내는 `DISCONNECTED`는 API와 데이터 모델에 유지하되, #36 Mock 화면은 앞의 세 상태를 모두 제공하여 표시를 검증합니다.

채널은 비활성화하거나 다시 활성화할 수 있습니다. 비활성 채널은 기존 프로젝트 이력에는 유지하지만 신규 프로젝트 생성과 일반 선택 목록에서는 제외합니다.

활성 채널에는 `수정`, `비활성화`, `관리에서 제거`를 표시하고 비활성 채널에는 `수정`, `재활성화`, `관리에서 제거`를 표시합니다. 버튼 문구는 줄바꿈하지 않고 공간이 부족할 때 버튼 전체가 다음 줄로 이동합니다. 제거 확인 모달에는 YouTube의 실제 채널은 삭제되지 않고 YMS에 등록한 채널 정보만 제거된다는 점과 되돌릴 수 없다는 점을 명시합니다. 서버 확인 결과 기존 프로젝트나 채널 귀속 업무 데이터에서 사용 중이면 해당 카드에 제거 불가 사유와 비활성화 안내를 표시하며, 연결 이력이 없으면 목록에서 제거합니다.

### 작업 종류 관리 영역

화면에서는 확장 가능한 Task Type을 `작업 종류`로 표시하여 제작팀에서 관리합니다.

- 기본 작업 종류
- 사용자 정의 작업 종류
- 새 작업 종류 추가
- 사용 여부 활성 / 비활성
- 작업 종류 삭제

가편집, 종합 편집, 자막과 썸네일은 초기 제공 데이터이며 사용자 정의 작업 종류와 동일하게 이름 수정과 비활성화가 가능합니다.

작업 종류 이름은 앞뒤 공백을 제거하고 영문 대소문자를 구분하지 않은 값을 기준으로 제작팀 안에서 중복을 차단합니다. 같은 이름의 비활성 작업 종류가 있으면 새 항목을 만들지 않고 기존 항목의 재활성화를 안내합니다.

비활성화된 작업 종류는 다시 활성화할 수 있습니다. 신규 작업 생성 목록에서는 제외하되 기존 작업 이력에는 유지합니다.

활성 작업 종류에는 `수정`, `비활성화`, `삭제`를 표시하고 비활성 작업 종류에는 `수정`, `재활성화`, `삭제`를 표시합니다. 세 버튼은 카드 안에서 같은 줄을 유지합니다. 삭제 전에는 되돌릴 수 없다는 확인 대화상자를 표시합니다. 서버 확인 결과 기존 작업에서 사용 중이면 해당 카드에 삭제 불가 사유와 비활성화 안내를 표시하며, 사용 이력이 없으면 목록에서 제거합니다.

### 관리 폼 이탈과 제작팀 전환

생성·수정 모달에서 입력값이 초기값과 달라진 경우 다음 동작 전에 확인 대화상자를 표시합니다.

- 모달 닫기
- 바깥 영역 클릭이나 `Escape` 입력 등 모달 닫기와 같은 결과를 만드는 동작
- 다른 관리 탭 선택
- 헤더에서 다른 제작팀으로 전환하는 동작
- 현재 화면을 벗어나는 내비게이션
- 브라우저 뒤로·앞으로 이동

사용자가 이탈을 승인하면 미저장 입력값을 별도로 보관하지 않고 폐기합니다. 변경이 없거나 저장을 완료한 상태에서는 확인 없이 닫거나 제작팀을 전환합니다. 제작팀 전환이 확정되면 열린 모달을 닫고 새 제작팀의 관리 데이터를 조회합니다.

생성·수정·삭제 확인 모달이 열리면 포커스를 모달 내부에 유지하고, 모달을 닫으면 모달을 열었던 버튼으로 포커스를 돌려보냅니다.

## 주요 상태 및 검증

- 마지막 OWNER의 권한 변경 또는 제거 차단
- OWNER 승격·강등의 이메일 재입력 2단계 확인
- 다른 OWNER 제외 시 대상 이메일 재입력 확인
- ACTIVE 멤버와 유효한 PENDING 이메일 재초대 차단
- LEFT·REMOVED 멤버 재초대 및 MEMBER 권한 복구
- ADMIN의 OWNER·ADMIN 조작과 사용자 승격 차단
- 취소된 초대 처리
- 만료된 PENDING 초대의 파생 상태 표시
- 다른 제작팀 리소스 접근 차단
- 프로젝트나 채널 귀속 업무 데이터에서 사용 중인 채널은 삭제를 거부하고 비활성화 안내
- 비삭제 Project 소유 멤버의 제외 차단과 소유권 이전 안내

# SCR-06. 프로젝트 그룹 관리

> 와이어프레임: [GitHub Pages에서 보기](https://heebaek200.github.io/yms-project/design/wireframes/scr-06-project-group.html)

## 목적

여러 영상 프로젝트의 비용과 외부 수익을 하나의 선택적 분석 단위로 묶어 관리합니다.

ProjectGroup은 제작팀 소속이며 특정 Channel을 직접 소유하지 않습니다.

프로젝트 그룹을 만들지 않아도 프로젝트 생성, 협업과 개별 성과 분석을 모두 이용할 수 있습니다.

## 접근 권한

- OWNER
- ADMIN

## 핵심 컴포넌트

### 프로젝트 영역 공통 탭

- 프로젝트: `/projects`
- 프로젝트 그룹: `/project-groups`

OWNER와 ADMIN에게는 두 탭을 같은 위치에 표시합니다. MEMBER에게는 프로젝트 탭만 표시합니다.

### 프로젝트 그룹 목록

- 프로젝트 그룹명
- 상태
- 시작일
- 종료일
- 연결 프로젝트 수
- 실제 비용
- 실제 수익
- 손익
- 상세 이동

기본 정렬은 ACTIVE, PLANNING, COMPLETED, CANCELLED 순서로 적용하고 같은 상태에서는 최근 시작일, 시작일이 없으면 최근 생성 순으로 표시합니다.

### 필터

- 상태
- 시작일·종료일 범위
- 이름·설명 키워드

기간 필터는 프로젝트 그룹 기간과 검색 기간이 하루라도 겹치면 포함합니다. 시작일이나 종료일이 없는 값은 해당 방향의 제한이 없는 기간으로 취급합니다.

프로젝트 그룹이 없으면 다음 선택 기능 안내와 생성 동작을 제공합니다.

> 여러 프로젝트의 비용과 외부 수익을 함께 분석하고 싶을 때 프로젝트 그룹을 만들어 보세요. 프로젝트는 그룹 없이도 관리할 수 있습니다.

### 프로젝트 그룹 생성 / 수정 모달

- 프로젝트 그룹명: 필수, 1자 이상 150자 이하
- 설명
- 시작일
- 종료일
- 상태: 생성 시 PLANNING
- 연결할 프로젝트 선택

같은 제작팀 안에서 앞뒤 공백을 제거하고 영문 대소문자를 구분하지 않은 이름의 중복을 차단합니다.

생성 과정에서 선택한 프로젝트가 대표인 VideoContent에 동기화된 성과 또는 계산 가능한 예상 플랫폼 수익이 있으면, 콘텐츠 성과가 새 프로젝트 그룹에 집계된다는 확인을 받은 뒤 생성과 연결을 함께 처리합니다. 확인을 취소하거나 검증이 실패하면 프로젝트 그룹과 일부 연결을 남기지 않습니다.

### 프로젝트 그룹 상세 영역

1. 그룹 이름, 설명, 상태와 기간
2. 실제 비용, 실제 수익, 손익과 ROI 요약
3. 연결된 프로젝트 목록과 연결 관리
4. 프로젝트 그룹 직접 Revenue 목록과 `수익 등록`
5. 프로젝트 그룹 직접 Expense 목록과 `비용 등록`

연결 프로젝트에는 각 프로젝트의 채널과 상태를 함께 표시합니다. 비용과 수익 등록 모달은 귀속 대상을 현재 프로젝트 그룹으로 고정하고, 전체 내역 이동 시 현재 프로젝트 그룹 필터를 유지합니다.

실제 비용은 그룹 직접 Expense, 소속 프로젝트 작업자 지급 금액과 소속 프로젝트 직접 Expense를 합산합니다. 실제 수익은 그룹 직접 Revenue와 소속 프로젝트 직접 Revenue를 합산합니다. 실제 비용이 0원이면 ROI는 `-`로 표시합니다.

## 주요 상태 및 검증

- 하나의 프로젝트는 최대 하나의 ProjectGroup에만 연결
- ProjectGroup 없이 존재하는 Project 허용
- 서로 다른 Channel의 Project를 하나의 ProjectGroup에 포함 가능
- OWNER와 ADMIN만 프로젝트 연결, 이동과 해제 가능
- 생성과 함께 연결, 상세에서 추가 연결, 이동과 연결 해제 시 같은 성과 이동 확인 정책 적용
- 대표 VideoContent의 동기화된 성과 또는 계산 가능한 예상 플랫폼 수익이 다른 그룹으로 이동할 때만 추가 확인
- 여러 프로젝트 일괄 연결은 전체 검증 후 한 번에 반영하고 실패 시 부분 적용 금지
- 이동 확인 시 프로젝트 직접 비용·수익의 집계 대상 변경 안내
- COMPLETED / CANCELLED 상태에는 새 프로젝트 연결 차단
- COMPLETED / CANCELLED 상태에서도 실제 비용·수익 등록과 정정 허용
- 연결 프로젝트, 직접 Expense와 직접 Revenue가 없는 그룹만 삭제 허용
- 삭제 전 서버에서 연결 데이터를 최종 확인하고 사용 중이면 상태 변경 안내
- 그룹과 프로젝트에 같은 외부 수익을 중복 입력하지 않도록 안내

## 화면 이동

- 프로젝트 선택 → SCR-08
- 성과 분석 → SCR-12
- 전체 비용·수익 → SCR-10, 현재 ProjectGroup 필터 유지

# SCR-07. 프로젝트 목록 / 생성 / 보관함

> 와이어프레임: [GitHub Pages에서 보기](https://heebaek200.github.io/yms-project/design/wireframes/scr-07-projects.html)

## 목적

현재 제작팀의 영상 프로젝트를 탐색하고 새 프로젝트를 생성하며 완료·취소 후 보관된 프로젝트를 조회합니다.

## 접근 권한

- 제작팀 멤버
- 조회 범위는 제작팀 및 프로젝트 권한에 따라 제한
- 프로젝트 생성 버튼은 현재 제작팀의 모든 ACTIVE 멤버에게 노출

## 핵심 컴포넌트

### 프로젝트 영역 공통 탭

- 프로젝트: `/projects`
- 프로젝트 그룹: `/project-groups`, OWNER와 ADMIN에게만 표시

### 프로젝트 목록

- 프로젝트 제목
- 채널
- 프로젝트 그룹
- 프로젝트 상태

일반 목록과 보관함은 같은 `/projects` Route에서 각각 `view=active`, `view=archived` Query Parameter로 구분합니다. 상태, Channel, ProjectGroup, 참여 여부와 키워드 필터도 URL Query Parameter로 유지하여 새로고침, 직접 링크와 브라우저 이력 이동 후 복원합니다. 일반 MEMBER는 자신이 참여한 프로젝트만 조회하고 OWNER와 ADMIN은 제작팀 전체를 조회하되 `내 참여 프로젝트` 필터를 사용할 수 있습니다.

### 검색 및 필터

- 상태
- 채널
- 프로젝트 그룹
- 참여 여부
- 보기: 진행 프로젝트 / 보관함

필터는 AND로 결합하고 키워드는 프로젝트 제목과 기획 내용을 검색합니다. 기본 정렬은 최근 수정 순이며 목록은 페이지네이션을 사용합니다. 제작팀 전환 시 페이지와 제작팀 종속 ID 필터를 초기화하고, 상세에서 목록으로 돌아오면 필터와 스크롤 위치를 복원합니다.

### 프로젝트 생성 / 수정 모달 또는 화면

- 프로젝트 제목
- 기획 내용
- 채널
- 프로젝트 그룹 선택, OWNER와 ADMIN만 변경 가능
- 영상 유형, LONG / SHORTS 중 기본 미선택
- 제작 마감일
- 업로드 예정일
- 초기 프로젝트 상태, PLANNING 기본값이며 PLANNING / EDITING 중 선택

프로젝트 그룹은 선택값이며 미선택을 기본값으로 사용합니다. MEMBER가 프로젝트를 생성하거나 수정하더라도 프로젝트 그룹 선택 필드는 제공하지 않고, 이미 연결된 그룹 이름만 읽기 전용으로 표시합니다.

제목, 활성 Channel, 영상 유형과 초기 상태는 필수입니다. 기획 내용과 두 일정은 선택값이며 일정 하나만 입력할 수 있습니다. 두 일정이 모두 있으면 제작 마감일이 업로드 예정일보다 늦을 수 없습니다. 과거 날짜와 수동 등록 Channel을 허용합니다.

생성·수정은 데스크톱에서 중앙 대형 모달, 모바일에서 화면을 거의 채우는 전체 화면형 모달로 표시합니다. 필드 순서와 하단 `취소 / 저장` 동작의 위치를 유지합니다. 생성 성공 후 새 프로젝트 상세로 이동하고 수정 성공 후 현재 상세 데이터를 갱신하며, 저장 성공 이동에는 이탈 확인을 표시하지 않습니다.

### 보관함

- UPLOADED 프로젝트
- CANCELLED 프로젝트
- 보관 해제

UPLOADED 또는 CANCELLED 상태만 보관할 수 있습니다. 프로젝트 소유자와 OWNER·ADMIN이 보관·해제할 수 있고, 보관 중 프로젝트를 PLANNING, EDITING 또는 REVIEW로 변경하면 자동으로 보관을 해제합니다.

# SCR-08. 프로젝트 상세 및 협업

> 와이어프레임: [GitHub Pages에서 보기](https://heebaek200.github.io/yms-project/design/wireframes/scr-08-project-detail.html)

## 목적

YMS 협업 기능의 핵심 화면입니다.

프로젝트 참여자가 프로젝트 정보, 작업 배정, 일정, 검수, 참여자 권한, 영상 결과물과 YouTube 게시 이력, 프로젝트 채팅을 한 화면에서 관리합니다.

## 접근 권한

- 프로젝트 소유자
- 프로젝트 참여자
- 같은 제작팀의 OWNER / ADMIN

프로젝트 권한:

- EDIT: 프로젝트 및 작업 수정 가능
- VIEW: 조회 및 채팅 가능, 프로젝트와 작업 수정 불가

프로젝트 소유자와 OWNER·ADMIN만 참여자를 추가·제거하고 EDIT / VIEW 권한을 변경할 수 있습니다. EDIT 참여자는 참여자와 권한을 조회할 수 있지만 변경할 수 없습니다. 프로젝트 그룹, 예상 수익 설정, 보관과 삭제도 프로젝트 소유자 또는 EDIT 권한만으로 변경할 수 없으며 각 기능의 별도 권한을 적용합니다.

OWNER와 ADMIN은 프로젝트 참여자로 자동 등록되지 않아도 제작팀의 모든 프로젝트를 조회하고 관리할 수 있습니다. 이 관리 접근만으로 프로젝트 채팅 참여 또는 읽음 상태를 만들지 않습니다.

### 영상 결과물 및 YouTube 게시물 영역

Project의 별도 독립 화면이 아니라 프로젝트 상세에서 모달 또는 Section으로 제공합니다.

영상 결과물 입력:

- 결과물 제목
- 영상 유형: LONG / SHORTS
- 연결 Project
- 대표 Project

YouTube 게시물 입력:

- YouTube URL 또는 Video ID
- 실제 게시 Channel
- 실제 게시 일시
- 조회수 1회당 적용 수익 단가 방식
  - Channel 기본 단가
  - 게시물 개별 단가
  - 수익 창출 없음

기능:

- 영상 결과물 생성 및 Project 연결
- 한 Project에서 여러 결과물 생성
- 여러 Project를 하나의 결과물에 연결
- 동일 결과물의 YouTube 게시물 추가 및 대체 게시물 지정
- 영상 유효성 확인
- URL은 HTTP·HTTPS의 허용된 YouTube 호스트와 `watch`, `shorts`, `youtu.be` 형식만 허용
- Workspace 내 동일 Video ID 중복 등록 확인
- 대체 게시물 ID는 같은 VideoContent와 Channel의 CURRENT 게시물과 일치하는지 확인
- 데이터 동기화
- 마지막 동기화 시각 표시
- Channel별 게시 이력 타임라인과 현재 게시물 강조
- 게시물 복원 및 명시적 대체 확인

일반적인 1 Project → 1 VideoContent 흐름에서는 사용자가 불필요한 단계를 느끼지 않도록 Project 기본값으로 결과물을 생성하고 바로 게시물을 추가할 수 있게 합니다. 분할 제작은 결과물을 추가하고, 합본 제작은 기존 결과물에 다른 Project를 연결하는 확장 동작으로 제공합니다.

프로젝트 소유자, EDIT 참여자와 OWNER·ADMIN은 자신의 관리 범위에서 영상 결과물과 게시물을 생성·수정할 수 있습니다. 같은 ProjectGroup 안에서 대표 Project를 변경하거나 양쪽 모두 그룹이 없으면 현재·새 Project를 모두 관리할 수 있어야 합니다. ProjectGroup 경계를 넘는 변경은 OWNER·ADMIN만 수행합니다. Channel 기본 단가, DEFAULT / CUSTOM / DISABLED 수익 방식, 적용 단가와 예상 플랫폼 수익은 OWNER와 ADMIN에게만 표시하고 변경을 허용합니다. 일반 MEMBER에게는 연결된 결과물의 조회수·좋아요·댓글만 표시합니다.

게시물에서 DEFAULT 방식을 사용 중일 때 게시 Channel 또는 VideoContent 영상 유형을 변경하면 새 기본 단가로 함께 변경된다는 안내를 저장 전에 표시합니다. CUSTOM과 DISABLED는 기존 설정을 유지합니다.

같은 VideoContent에 여러 YouTube 게시물이 있으면 Channel별 시간순 타임라인으로 묶고 `게시 중(CURRENT)` 게시물을 강조합니다. `대체됨(SUPERSEDED)`, `게시 종료(REMOVED)`와 UNAVAILABLE / INCORRECT 종료 사유 및 대체 관계를 함께 표시합니다. 같은 Channel에 게시 중인 게시물이 있는 상태에서 새 게시물을 등록하거나 과거 게시물을 복원할 때는 어떤 게시물을 대체하는지 명시적으로 확인합니다. 기존 게시물의 조회수와 동기화 이력은 새 게시물을 추가해도 유지합니다.

프로젝트·VideoContent 목록은 현재 성과를 주 지표로 표시합니다. 프로젝트 상세은 현재 성과와 누적 게시 성과를 나란히 제공하고, ProjectGroup·분석 화면은 누적 게시 성과를 주 지표, 현재 성과를 보조 지표로 표시합니다. 게시물 목록은 합계가 아니라 각 게시물 자체의 성과를 표시합니다. 조회수·좋아요·댓글과 예상 플랫폼 수익은 같은 현재·누적 포함 기준을 사용합니다.

성과 합계 옆에는 COMPLETE / PARTIAL / UNAVAILABLE 상태와 포함·미집계 게시물 수를 표시합니다. 한 번도 동기화에 성공하지 않은 게시물은 `0`이 아닌 `미집계`로 표시합니다. 성공 이력이 있는 동기화 실패는 마지막 성공값을 유지하면서 `확인 필요`, 마지막 성공 시각, 마지막 시도 시각과 오류를 보여주며 게시물을 자동으로 `게시 종료` 처리하지 않습니다.

대표 Project 변경으로 콘텐츠 성과가 다른 ProjectGroup으로 이동하면 저장 전에 영향 확인 모달을 표시합니다. 대표 Project를 삭제할 때 다른 활성 연결 Project가 있으면 결과물별 새 대표를 사용자가 선택합니다. 후보가 하나뿐이면 미리 선택하되 확인은 생략하지 않습니다. 후보가 없으면 결과물·게시 이력을 보존하고 삭제된 Project를 역사적 대표로 표시하며 활성 집계에서는 제외합니다.

### 보관과 삭제

UPLOADED와 CANCELLED 프로젝트만 보관할 수 있으며 프로젝트 소유자와 OWNER·ADMIN이 보관하거나 해제할 수 있습니다. 삭제는 같은 권한에서 확인 모달을 거친 뒤 논리 삭제합니다. 삭제할 Project가 하나 이상의 VideoContent 대표이면 확인 모달에서 결과물별 대표 이전 필요 여부와 콘텐츠 성과의 ProjectGroup 이동 영향을 함께 표시합니다. 삭제 프로젝트는 업무 목록과 콘텐츠 성과에서 제외하지만 실제 비용·수익·정산 이력은 재무 합계와 출처 표시에 유지합니다.

### 프로젝트 폼 이탈 보호

생성·수정 모달의 입력값이 초기값과 달라지면 닫기, 취소, Escape, 바깥 영역 클릭, 다른 프로젝트·탭·헤더 메뉴·프로필 이동, 브라우저 뒤로·앞으로 이동과 제작팀 전환 전에 확인합니다. 사용자가 취소하면 현재 URL·화면과 입력값을 유지하고 승인하면 입력값을 폐기합니다. 값을 원래대로 되돌렸거나 저장이 성공한 경우에는 확인하지 않습니다.

저장 실패 메시지는 모달 안의 관련 필드 또는 모달 공통 오류 영역에 표시하고 입력값을 유지합니다. 인증 만료, 로그아웃 또는 제작팀 접근 상실은 보안 흐름을 우선하여 이탈 확인 없이 처리합니다.
- 작업 종료일 > 프로젝트 마감일 경고
- 검수 반려 및 재검수
- 잘못된 YouTube URL / Video ID
- YouTube API 오류와 입력 오류 구분
- 동일 영상의 다른 Project 중복 연결 차단

# SCR-12. 콘텐츠 성과 및 재무 분석

> 와이어프레임: [GitHub Pages에서 보기](https://heebaek200.github.io/yms-project/design/wireframes/scr-12-analytics.html)

## 목적

OWNER와 ADMIN이 콘텐츠에 실제로 투입한 비용과 실제 발생한 수익을 비교하고 Project와 ProjectGroup의 재무 성과를 확인합니다.

조회수와 같은 콘텐츠 반응 지표는 재무 성과와 분리하여 참고 정보로 함께 제공합니다.

## 접근 권한

- OWNER
- ADMIN

일반 MEMBER에게 전체 비용, 매출, 손익 또는 ROI를 노출하지 않습니다.

## 핵심 컴포넌트

### 분석 단위 선택

초기 핵심 분석:

- Project
- ProjectGroup

확장 조회:

- Channel
- 제작팀

### 재무 요약 카드

- 실제 비용
- 실제 수익
- 손익
- ROI
- 수익 / 비용 배수

계산:

```text
손익 = 실제 수익 - 실제 비용

ROI = (실제 수익 - 실제 비용) ÷ 실제 비용 × 100

수익/비용 배수 = 실제 수익 ÷ 실제 비용
```

실제 비용이 0원인 경우 ROI는 계산하지 않고 '해당 없음'으로 표시합니다.

### Project 분석

비용:

- 작업 담당자 지급 금액
- Project 직접 Expense

수익:

- Project 직접 실제 Revenue

콘텐츠 참고 지표:

- 조회수
- 좋아요
- 댓글 등 연동 가능한 지표
- 조회수 1회당 단가 기반 예상 YouTube 플랫폼 수익

예상 수익은 실제 ROI 계산에 포함하지 않습니다.

### ProjectGroup 분석

비용:

- ProjectGroup 직접 Expense
- 연결 Project의 작업자 지급 금액
- 연결 Project의 직접 Expense

수익:

- ProjectGroup 직접 실제 Revenue
- 연결 Project의 직접 실제 Revenue

추가 정보:

- 포함 Project 수
- Project별 상태
- Project별 Channel
- Project별 콘텐츠 성과

Channel 또는 제작팀에 직접 귀속된 Expense / Revenue는 ProjectGroup에 자동 배분하지 않습니다.

### 시각화

초기 버전에서는 다음 정도로 제한합니다.

- 실제 수익 / 실제 비용 비교
- 수익 유형별 구성
- Project별 비용·수익 비교
- ProjectGroup 내 Project별 콘텐츠 성과
- 프로젝트 상태 또는 진행 현황

## 주요 상태 및 검증

- 실제 수익 0원 정상 처리
- 실제 비용 0원 시 ROI 계산 불가 처리
- 추정 수익과 실제 수익 시각적으로 구분
- ProjectGroup과 Project의 Revenue 중복 집계 방지
- 권한 없는 사용자 접근 차단
- 외부 API 갱신 실패 시 마지막 성공 데이터와 갱신 시각 표시

## 7. HTML 와이어프레임 관리 규칙

화면 와이어프레임은 정적 이미지가 아니라 **최소한의 HTML과 공통 CSS로 작성한 구조 설계도**를 기준으로 관리합니다.

실제 서비스 디자인, JavaScript 동작, API 호출, 캘린더·차트·WebSocket 라이브러리는 구현하지 않습니다. 화면 영역, 정보 배치, 반응형 구조와 주요 컴포넌트의 위치를 검토할 수 있는 수준까지만 표현합니다.

파일은 다음 경로에서 관리합니다.

```text
docs/
└─ design/
   ├─ 화면 설계.md
   └─ wireframes/
      ├─ index.html
      ├─ wireframe.css
      ├─ scr-01-auth.html
      ├─ scr-02-profile.html
      ├─ ...
      └─ scr-12-analytics.html
```

공통 레이아웃과 반응형 규칙은 `wireframe.css`에 두고, 각 화면은 자신의 구조만 HTML로 작성합니다.

- [GitHub Pages 와이어프레임 인덱스](https://heebaek200.github.io/yms-project/design/wireframes/)

데스크톱과 모바일은 별도 이미지 파일로 분리하지 않습니다. 동일한 HTML에 최소한의 미디어 쿼리를 적용하여 브라우저 폭을 변경하면서 레이아웃 전환을 확인합니다.

캘린더, 차트, 표, 메신저 등 복잡한 컴포넌트도 실제 라이브러리를 사용하지 않고 `flex`, `grid`, `border` 등의 CSS로 구조만 표현합니다.

화면 간 이동 관계는 본 문서의 Mermaid 다이어그램을 기준으로 유지합니다.

## 8. 다음 설계 단계

SCR-01~12의 화면 책임과 1차 HTML 와이어프레임 작성은 완료된 상태입니다.

이후에는 각 와이어프레임을 실제로 확인하면서 다음 항목을 순차적으로 보완합니다.

1. 화면별 정보 우선순위와 영역 배치 검토
2. 모바일 레이아웃 검토
3. 모달 / Drawer 등 보조 UI 구체화
4. 로딩 / 빈 데이터 / 오류 상태 추가
5. 버튼 및 사용자 액션 흐름 확인
6. 화면별 관련 API 매핑
7. 최종 React 화면 구현과의 차이 정리

와이어프레임은 실제 UI 디자인 시안이 아니라 요구사항과 사용자 시나리오를 검증하기 위한 구조 문서로 유지합니다.
